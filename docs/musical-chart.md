# 音源解析による譜面生成

音源はブラウザ内で解析する。音の立ち上がり、帯域別の変化、目立つ音の高さから Tap 譜面を作り、Easy / Normal / Hard で間隔と密度を制限する。無音にはノーツを足さない。リズム重視 / バランス / メロディー重視を選べる。

解析は Web Worker で行い、同じ音源・設定から同じ譜面を得る。短時間フーリエ変換の対数スペクトルの正の差分と局所閾値で発音候補を検出する。高さは混合音源の目立つスペクトル成分からの推定であり、ボーカル分離や正確なメロディー採譜ではない。推定テンポは参考表示に使い、検出時刻を強制的に等間隔に丸めない。

生成結果は JSON 保存・読込に対応。音源は含めず、元音源の SHA-256、長さ、レーン、生成設定、ノーツを保存する。同じ音源を選んで読み戻す。入力判定の補正（正値は遅い入力を許容する）も保存する。

安全な負荷上限として音源は100 MB・15分まで。解析のキャンセル、進捗表示、失敗時の再試行を提供する。曲や生成設定の切替中とプレイ中は編集をロックする。

## 検証

合成音源で発音時刻、無音、音色・高さの変化、難易度の間隔制限、再現性を検証する。音源読込失敗と再生終了・再挑戦、JSON の検証も対象とする。実曲の聴感と楽しさはユーザーによるプレイ調整が必要。

- ブラウザでJSONダウンロードと同じ音源への読込に成功。別の音源では読込を拒否。壊れた音源の読込に失敗しても元の曲と譜面は保持。

## 4レーン表示（2026-10-16）

- A / W / S / Dを0.36単位間隔で配置。初期の円では内側からこの順。
- 時刻から距離への変換は中心線の弧長テーブルだけを使う。各レーン独自の距離時計は作らない。同じ時刻の横断位置から線・ノーツ・判定バー・エフェクトを配置する。
- カーブでは外側の移動距離が長くなるが、4本の進行率と判定タイミングは同じ。内側が先行することはない。
- オフセット線は頂点の法線を使ったマイター接続。鋭角の突き出しは2倍までに制限。レーン幅より小さな半径の急折り返しでは線同士が交差しうるため、ステージ形状には十分な曲率半径を確保する。
- 既存の譜面JSONはそのまま利用できる。画面下の補助ガイドも同じキー順・色の4段表示。
- `npm test`: 13件成功。直線の等間隔、円の共通角度と閉路端、左右に曲がる非対称経路、ノーツ・バー・エフェクトの一致、重複頂点を検証。`npm run build` 成功。ブラウザで4本の表示・バーの移動・キー別ノーツ・自然終了を確認。

## レーン数の切り替え（2026-10-16）

- 開発パネルで1〜4本を選択。1本 `[A W S D]`、2本 `[A W] [S D]`、3本 `[A W] [S] [D]`、4本 `[A] [W] [S] [D]` の固定割り当て。
- `createLaneLayout` が線の位置・担当キーを一元管理。共有レーンは中立色、ノーツと文字は元のキー色。レーン・バー・エフェクト・ガイド・凡例をまとめて更新する。
- 切り替えは停止中のみ。譜面を再解析せず、既存のノーツ時刻とキーを保って再配置し、スコアをリセットする。
- JSONの省略可能フィールド `laneCount` に保存する。旧形式の省略時は4本、1〜4の整数以外は読込を拒否する。
- テスト18件成功。全レーン数で4キーの重複・欠落がないこと、カーブ上でノーツ・バー・エフェクトが一致すること、JSON往復・旧形式・不正値を確認。ブラウザで1→2→3→4→2の切り替え、ノーツ数の維持と2本での再生を確認。

## プレビューコース5種（2026-10-16）

- `PreviewCourses.js` に周回3種（ワインディング、クローバー、立体8の字）と片道2種（つづら折り、スパイラル）。円は比較用に残す。十分な折り返し半径と高密度の点列で1〜4本のオフセットを保持する。
- 全形状で同じ中心線の弧長時計を使い、1曲で始点から終点まで進む。長さを増やしても音源やノーツ時刻は変更しない。
- 形の変更時は線・判定バー・ノーツを再配置し、カメラをパネルと下部ガイドの間に自動フィット。STARTボタンは形を隠さない左上へ移動。
- バージョン付きの `laneId` を既存JSONに保存。読込時は既知コースを復元し、未知の形状IDは拒否する。従来の円のJSONにも対応。
- コースの連続性、内側の折り返しの反転防止、全レーン数の同期、立体交差の高低差、複数画面比率でのカメラ範囲、JSONによる形の復元をテスト。

## 音楽付き保存一覧（2026-10-16）

- `AudioManager` はデコード前に元の音源をBlobとして保持する。Web Audioが入力ArrayBufferをdetachしても、元のバイト列とSHA-256を保存・復元できる。失敗時は現在の曲を保持。
- `StageLibrary` はIndexedDBにステージ本体と一覧用メタデータを別ストアで保持し、1つのトランザクションで追加する。一覧の取得で全音源を読む必要はない。成功表示はトランザクション完了後。
- 各保存は新規ID。音楽・譜面・形・本数・補正・判定設定・生成設定を含む。既存の保存を暗黙に上書きしない。
- `.soundstage` は8バイトの形式識別子、4バイトのJSON長、UTF-8の設定JSON、元音源の順。base64化せず、音源サイズを膨らませない。音源100 MiB・設定約2 MBの上限を検証。
- 復元は候補の音源をデコードし、ハッシュ・長さ・形・ノーツを検証してから現在のゲームに反映する。再解析はせず、保存済みの配置をそのまま使う。壊れた保存や別の音源を混ぜた保存は拒否。
- 既存JSONの最短50 ms間隔検証は浮動小数点誤差を許容し、等間隔譜面の自己保存・読込を維持する。
- ブラウザ保存の範囲とサイトデータ削除時の扱いをUIに明示。バックアップ・別ブラウザへの移行にはファイル書出しを使う。

## 音色で統一（2026-10-16）

- 「拾う音」に `音色で統一`（`focus: 'timbre'`）を追加。同じ種類の音は、できるだけ同じキーで押せるようにする。
- 解析（`version: 2`）では、各発音の立ち上がりで新しく増えた音のエネルギーが、8つのオクターブ帯域にどう分布するかを記録する（`event.timbre`）。増えた分だけを見るので、伸びている和音やボーカルがあっても、スネアなどの指紋は変わりにくい。帯域ごとのビン数で正規化し、平方根を取った単位ベクトルにしている。
- 譜面生成では、Hard でも残りうる候補を k-means で2〜4グループに分ける。初期値は明るさ順に均等に取り、結果を決定的にする。シルエット係数が最良から0.05以内なら、グループ数の多い方を選ぶ。グループは暗い順に、2つなら A/D、3つなら A/S/D、4つなら A/W/S/D に割り当てる。これでレーン数を変えても、別のグループが同じ線に重なりにくい。
- キーは選択の前に決める。同じキーの最短間隔（`sameKeyGap`）は、キーを付け替えるのではなく、ノーツを間引いて守る。間隔・密度上限は他のモードと同じ。
- 曲によってはグループが2つに収まる。付属の24秒音源では、2種類の打音が交互に鳴るため A/D の交互になる。混合音源からの推定なので、楽器を完全に分離できるわけではない。
- テスト: 和音の上に、合成したバスドラム・スネア・ハイハットを鳴らす。全難易度で、各音の90%以上が同じキーになり、音ごとに別のキーになることを確認。従来モードでは、スネアが W/S/D/A に散っていた。

## ゲームパッド（2026-10-16）

- `src/input/GamepadInput.js` は、標準マッピングのボタン番号を W/A/S/D に変換する。X(2)→A、Y(3)→W、A(0)→S、B(1)→D、メニュー(9)→START/停止。判定には、キーボードと同じ `processKeyInput` を使う。
- Gamepad API はポーリングでしか読めない。そこで `gamepadconnected` 以降、接続中は `requestAnimationFrame` で読み続ける。押した瞬間だけを1回の入力として扱い、押しっぱなしは無視する。`pad.timestamp` から経過時間（最大50 ms）を求め、その分を判定時刻から引く。フレームの遅れで判定が遅くならないようにするため。
- 最後に使った入力に合わせて、表示する文字を切り替える。対象は凡例、レーン順、下のガイド、ノーツのラベル、停止ボタン。譜面・保存データのキーは W/A/S/D のまま。
- テスト: ボタン対応、押下の立ち上がりだけを検出すること、経過時間の上限、ラベル、メニューでの開始・停止、判定時刻の補正。ブラウザでは疑似パッドを使い、表示の切替、4ボタンの判定、メニューでの開始・停止、キーボードでの表示の戻りを確認。実機のコントローラーでは未確認。

## 追従カメラ・ガイドの非表示・判定エフェクト（2026-10-16）

- `src/core/FollowCamera.js` は、カメラの向きと見せる範囲を決める。範囲は約1.5秒分の移動距離（コース長 ÷ 曲の長さ × 1.5）で、2.5〜9の間に収める。`chase` では、0.6範囲先の中心線上の点へ向かう水平方向を「前」にする。カメラは現在地の後ろ上方に置き、少し先を注視する。`GameRenderer.follow` は位置と注視点を時定数約0.2秒で補間するので、ヘアピンでも視点が飛ばない。停止すると `showOverview` で全体表示に戻る。
- レーンの横方向ベクトルの向きを反転し、進行方向の右を正にした。追従カメラで A が左・D が右になり、キーボードの A/D やパッドの X/B と左右が一致する。全体表示では、コースの内側と外側が入れ替わって見える。譜面データや判定には影響しない。
- 開発パネルの `カメラ` 欄に `カメラの距離`（0.5〜2.5倍）を置いた。`followSpan` に掛ける倍率で、プレイ中も変更できる（他の操作はプレイ中は無効のまま）。スライダーから指を離すとフォーカスを外し、キー入力をゲームに戻す。従来の `レーンの拡大` は `全体表示の拡大` に名前を変え、全体表示だけに効く。
- 画面下の譜面ガイドは非表示にできる。非表示にすると描画を止め、3Dビューと設定パネルを下まで広げる。設定は `localStorage`（`soundgame.view`）に保存し、使えない環境でも動作は変わらない。
- 判定エフェクトは `createJudgementEffect` が作る。良い判定ほど大きく長く派手で、Miss だけは広がらずに揺れて沈む×印。時間は `performance.now()` 基準にし、フレームレートで長さが変わらないようにした。
- テスト: 全5コースで、追従時の左右が A<W<S<D の順になること。見せる範囲の上下限。判定ごとの大きさ・長さ・部品数の順序と、終了時に消えること。ブラウザでは追従表示、停止時の全体表示への復帰、ガイドの非表示と再読み込み後の保持、4種類のエフェクトを確認。
- 制約: コースは1曲で1周するので、長い曲ほど移動が遅くなり、ノーツどうしが空間上で詰まる。3分の曲をワインディングで遊ぶと、Normal の最短間隔のノーツは約0.08しか離れず、ノーツ本体の幅（約0.26）より近い。追従カメラは範囲の下限を2.5にしているが、これだけでは解消しない。

## itch.io 向けの調整（2026-10-16）

- `カメラの距離` の初期値を1.5倍にした。距離を保存するのは、プレイヤーがスライダーを動かしたときだけ（`cameraDistance`）。初期化時には保存しない。以前のバージョンは起動時に毎回 `distance: 1` を自動で書き込んでいたため、その値は読まずに捨てる。
- Shift + P（`e.code === 'KeyP'` で判定し、IME の状態に左右されない）で、開発パネルと譜面ガイドの表示をまとめて切り替える。プレイ中でも使える。文字入力欄では無効にし、ボタン・スライダー・チェックボックスにフォーカスがあるときは有効。隠したパネル内にフォーカスが残っていればそれを外す。パネルを隠すと3Dビューが全幅を使う（`GameRenderer.setPanelVisible`）。設定は `devUi` として保存する。
- `SoundGame_itch.zip` を現在の `dist/` から作り直した。本番ビルドを `vite preview` で開き、解析ワーカーを含めてエラーなく譜面が生成されることを確認した。
